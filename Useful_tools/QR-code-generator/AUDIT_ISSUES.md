## 2. Issue Details & Technical Remediation

### ISS-01: Multilingual Unicode Byte Truncation in QR Engine
- **Severity:** P1 (High)
- **Affected Feature:** All QR Content Types with non-Latin text (Sinhala, Tamil, Japanese, Chinese, Arabic, Accented European characters, Emojis).
- **Evidence:** `jsQR` failed to decode `'Multilingual: 日本語, العربية, සිංහල, தமிழ், English'` generated by the matrix engine.
- **Root Cause:** The bundled `qrcode.min.js` defaults to `stringToBytesFuncs['default']`, which performs `255 & charCode`. Characters with code points > 255 had their upper bytes discarded, corrupting the QR matrix.
- **Remediation:** In `main.js`, explicitly configure:
  ```javascript
  if (window.qrcode && window.qrcode.stringToBytesFuncs && window.qrcode.stringToBytesFuncs['UTF-8']) {
    window.qrcode.stringToBytes = window.qrcode.stringToBytesFuncs['UTF-8'];
  }
  ```
- **Files Modified:** `main.js`
- **Verification:** Independent decoding via `jsQR` achieved 100% payload recovery across multi-script strings.

### ISS-02: SVG Export Injected Relative External File Link
- **Severity:** P1 (High)
- **Affected Feature:** Scalable Vector SVG Export (`main.js:1355`).
- **Evidence:** Inspecting exported SVG markup revealed:
  `<image x="256.00" y="256.00" width="88.00" height="88.00" href="../../Src/favicon-HzGPD.png" />`
- **Root Cause:** When the preset logo `hzgpd` was active, the SVG generator referenced the image element's relative `.src` path instead of embedding an inlined data URI.
- **Impact:** Downloaded SVG vector files failed to render the center logo when opened in Illustrator, Inkscape, Figma, or outside the local workspace.
- **Remediation:** Convert `hzgpdLogoImg` to an inlined Base64 data URI (`data:image/png;base64,...`) when compiling the SVG vector string.
- **Files Modified:** `main.js`
- **Verification:** Exported SVG verified to be 100% self-contained and portable with zero external network or relative filesystem dependencies.

### ISS-03: Manifest Icon Scope & Service Worker Precache Gap
- **Severity:** P2 (Medium)
- **Affected Feature:** PWA Installability and Offline Capabilities.
- **Evidence:** `manifest.webmanifest` defined `"src": "../../Src/favicon-HzGPD.png"`, which lies outside the service worker's directory scope. Additionally, `sw.js` did not list the local icon `./hzgpdfavicin.png` in `ASSETS`.
- **Root Cause:** Legacy relative path referencing parent workspace directory before local favicon was created.
- **Remediation:**
  1. Updated `manifest.webmanifest` icon sources to `./hzgpdfavicin.png`.
  2. Added `./hzgpdfavicin.png` to `ASSETS` in `sw.js`.
  3. Updated `index.html` favicon link to `./hzgpdfavicin.png`.
- **Files Modified:** `manifest.webmanifest`, `sw.js`, `index.html`
- **Verification:** Tested clean service worker precache installation; verified icon loads while fully offline.

---

### ISS-04: String Concatenation in Toast Notification innerHTML
- **Severity:** P3 (Low)
- **Affected Feature:** UI Feedback System (`showToast()`).
- **Evidence:** In `main.js`, `toast.innerHTML = ${iconSvg}<span>${msg}</span>;`.
- **Root Cause:** Direct interpolation into `innerHTML` could theoretically allow HTML injection if an unsanitized error string contained metacharacters.
- **Remediation:** Create a dedicated `<span>` element and set `span.textContent = msg`, appending it cleanly to the toast container.
- **Files Modified:** `main.js`
- **Verification:** Verified all toast messages render cleanly and safely without any HTML parsing risks.
